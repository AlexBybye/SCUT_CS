<h1 align='center'>SCUT_SKILL · 学生向 AI Skill 索引</h1>

> **这里不放 skill 本体，只放索引。** 想找具体清单，直接看 [Summary_Skill.md](Summary_Skill.md)。
> 这份 README 只讲三件事：为什么建、收什么、怎么提交。

## 一、为什么建这个文件夹

**方法上的信息差，比资料上的信息差更大。**

>这两年学院同学手上普遍已经有 Claude Code、Codex、Cursor 这类 Agent 工具，但用法大多还停留在把 PDF 拖进去问一句。Agent Skill 能把一套稳定的做法固定下来反复用 —— 写好一次，之后每次都按同样的标准跑，不必每回重新拼提示词。方法上的信息差比资料上的信息差更大，而后者正是本仓库一直在打破的东西。

所以这个文件夹只做一件事：**让 SCUTCSer 互相交换已经验证过好用的 skill 索引。**

它也是主 README 里第三期仓库建设 🔴 高等目标（基于本仓库资源的 RAG agent 及 skill 市场）的后半部分，先把有哪些 skill、谁写的、能干什么、边界在哪攒成一份清单，在智能复习助手后期迭代中怎么都不会白做。

### 为什么只放链接，不把 skill 拷进来

1. **skill 会迭代**：拷一份进来，就是拷了当天的快照。一个月后作者改了三版，这里还是旧的 —— 主 README 第一条批判的"更新时间古早，不具有时效性"，说的就是这种情况。
2. **著作权归作者**：你在自己仓库里写的东西，Stars、Issue、贡献记录都该记在你自己名下，而不是归功给收集者，这个仓库只是曝光平台。

### 目录结构

```text
SCUT_SKILL/
├── README.md            ← 你在这（初衷 + 贡献标准 + 提交方式）
└── Summary_Skill.md     ← skill 清单：超链接 + 介绍 + 边界
```

作者在**自己的仓库**里写好 skill，然后向本仓库提 PR，**只往 `Summary_Skill.md` 里加一条**。不用动别的文件。

## 二、收什么，不收什么

### 达到以下标准的，欢迎提 PR

| 项             | 要求                                                                  | 为什么                       |
| -------------- | --------------------------------------------------------------------- | ---------------------------- |
| **来源** | 你自己写的，或你**实际用过**的第三方 skill                      | 不收纯搬运的"我看到有人推荐" |
| **规范** | 仓库里有`SKILL.md`，符合 [Agent Skills 规范](https://agentskills.io) | 别人 clone 下来能直接用      |
| **边界** | 介绍里必须写**它不做什么**                                      | 见下                         |
| **安全** | 建议先用`skill-scanner` 扫一遍再提交                                | 见下                         |
| **性能** | 如果是个人写的建议先用`skill-forge` 优化一下再提交，但要注意优化是否成立，培养审计AI的能力                                |   见下   |

许可不做硬性要求。有 LICENSE 的话在清单里注明一下，别人想改、想拿去用的时候知道边界在哪；没有也照样能提。

**关于必须写边界**：这是这份清单和市面上那些 awesome 列表最主要的区别。只写优点的介绍，等于让读者自己去踩坑。Skill 说到底是喂给 Agent 的指令，写得含糊 Agent 就会越权 —— 你只想让它润色一段话，它顺手把你的结论也改了。所以每条都要写清能力止于何处。

**关于安全扫描**：Skill 会被 Agent 直接执行，有提示词注入和数据外传的风险。清单里收 Cisco 的 `skill-scanner` 就是为了这个，装任何第三方 skill 前先扫一遍，成本很低。这件事和 `信息安全`、`面向互联网+的数据安全` 两门课直接对得上，拿它当课程作业的实践对象也合适。

**关于性能优化**：优秀的大模型现在好多skill的规范是在默认中有所包含，且skill在实际跑的时候不断进行优化就像给衣服不停的打补丁，上述可能最终会使得一个日后经常使用的skill反复消耗本不必花费的token，故优化至关重要。

### 以下不收

- 纯 prompt 模板（没有 `SKILL.md`、没有结构、复制粘贴即用的那种）
- 需要把本仓库**加密资料**、他人作业或任何私人数据上传到第三方服务的
- 功能就是"替你把作业写完交上去"的
~~这种怎么能收录呢？~~

最后一条得多说一句。主 README 结尾那句 **"请诚信学习"** 在这里同样成立，而且更要紧 —— 资料至少还得你自己读，Agent 是能直接产出可提交内容的。工具帮你更快地理解，不帮你伪造你没有的理解。校内查重和维普查重摆在那儿，为自己的行为负责。

## 四、关于夹带私货的自我举报 (🐶)
`Summary_Skill.md` 里「本院开发」那一栏，好几个是本仓库维护者自己写的。链接自己加的，介绍自己写的，审稿人……也是自己。

也正因如此，**特别欢迎屏幕前的你来贡献自己的 skill 把这一栏冲淡一点。** 不用觉得自己写的不够好 —— 一个只解决了你一门课痛点的小 skill，对同专业的下一届可能正好够用。愿开源精神在 SCUT 发扬。🚩
