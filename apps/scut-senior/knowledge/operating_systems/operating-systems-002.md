<!-- question: operating-systems-002-Q13 -->

3. 调度算法（作业/进程调度）

先来先服务（FCFS）：按提交时间顺序调度。

最短作业优先（SJF，非抢占式）：从已到达的作业中选择执行时间最短的。

周转时间与等待时间计算：定义及公式：

周转时间 = 完成时间 − 提交时间

等待时间 = 周转时间 − 执行时间

平均周转时间、平均等待时间。

算法评价指标：平均周转时间、平均等待时间、公平性、饥饿现象等。

两种算法比较：FCFS 对短作业不利，SJF 能减少平均周转时间但可能导致长作业饥饿。

<!-- question: operating-systems-002-Q21 -->

一、题目描述

有两个并发进程  P1  和 P2，它们共享  2  个缓冲区 B：
- P1  每次向缓冲区  B  中放入一个数据项产品；
- P2  每次从缓冲区  B  中取出一个数据项产品；

要求：

<!-- question: operating-systems-002-Q22 -->

1. 不允许从空缓冲区中取数据；

<!-- question: operating-systems-002-Q23 -->

1. 不允许对同一数据项进行重复取用；

系统采用信号量以及  down / up  操作实现进程间的同步与互斥。

<!-- question: operating-systems-002-Q24 -->

二、信号量设置

| 信号量 | 初值 | 作用 |
|---|---|---|
| mutex | 1 | 互斥信号量，保证同一时刻只有一个进程访问缓冲区（临界区） |
| empty | 2 | 表示缓冲区空槽数，控制生产者是否可以放入数据 |
| full | 0 | 表示缓冲区已存放的数据项数，控制消费者是否可以取数据 |

<!-- question: operating-systems-002-Q25 -->

三、伪代码

生产者 P1（放入数据项）

void  P1(void) {     int  item;     while (TRUE) {                 item  =  produce_item();   // 生产一个数据项                 down(&empty);            // 等待缓冲区有空位                 down(&mutex);            // 进入临界区                 insert_item(item);       // 将数据项放入缓冲区                 up(&mutex);              // 离开临界区                 up(&full);               // 增加已存放数据项数     } }

消费者 P2（取出数据项）

void  P2(void) {     int  item;     while (TRUE) {                 down(&full);             // 等待缓冲区有数据                 down(&mutex);            // 进入临界区                 item  =  remove_item();    // 从缓冲区取出数据项                 up(&mutex);              // 离开临界区                 up(&empty);              // 增加空槽数                 consume_item(item);      // 使用数据项     } }

<!-- question: operating-systems-002-Q26 -->

四、说明

<!-- question: operating-systems-002-Q27 -->

1. **互斥**
  - mutex 保证缓冲区的访问是互斥的，防止生产者和消费者同时操作缓冲区导致数据错误或重复取用。

<!-- question: operating-systems-002-Q28 -->

1. **同步**
  - empty 控制生产者：缓冲区满时阻塞生产者。
  - full 控制消费者：缓冲区空时阻塞消费者。

<!-- question: operating-systems-002-Q29 -->

1. **down / up** **操作**
  - down(S) 等价于 P(S)，即等待信号量可用；
  - up(S) 等价于 V(S)，即释放信号量。

<!-- question: operating-systems-002-Q44 -->

二、解题步骤与推导过程

Step  0：初始状态  t0
- 各进程占有资源均为  0
- 系统可用资源：12
- 可运行进程：P0、P1

Step  1：t1 时刻（请求：P0  -> 3, P1 -> 2, P2 ->  4）

1.1  处理  P0 -> 3
- P0  当前占有  =  0，最大需求  = 5 →  还需  5
- 请求  3 ≤  5，系统可用资源  = 12 ≥ 3 →  分配成功
- 占有资源：P0=3,  P1=0, P2=0, P3=0
- 系统可用资源  = 12 - 3 = 9

1.2  处理  P1 -> 2
- P1  当前占有  =  0，最大需求  = 4 →  还需  4
- 请求  2 ≤  4，系统可用资源  = 9 ≥ 2 →  分配成功
- 占有资源：P0=3,  P1=2, P2=0, P3=0
- 系统可用资源  = 9 - 2 = 7

1.3  处理  P2 -> 4
- P2  当前占有  =  0，最大需求  = 7 →  还需  7
- 请求  4 ≤  7，系统可用资源  = 7 ≥ 4 →  分配成功
- 占有资源：P0=3,  P1=2, P2=4, P3=0
- 系统可用资源  = 7 - 4 = 3

✅安全序列存在，例如  P1→P0→P2→P3

Step  2：t2 时刻（请求：P1  -> 1, P3 ->  5）

2.1  处理  P1 -> 1
- P1  当前占有  =  2，最大需求  = 4 →  还需  2
- 请求  1 ≤  2，系统可用资源  = 3 ≥ 1 →  分配成功
- 占有资源：P0=3,  P1=3, P2=4, P3=0
- 系统可用资源  = 3 - 1 = 2

2.2  处理  P3 -> 5
- P3  当前占有  =  0，最大需求  = 6 →  还需  6
- 请求  5 ≤  6，但系统可用资源  = 2 < 5 →  阻塞
- 占有资源不变：P3=0*（被阻塞）
- 系统可用资源  = 2

Step  3：t3 时刻（请求：P0  -> 2, P2 ->  2）

3.1  处理  P0 -> 2
- P0  当前占有  =  3，最大需求  = 5 →  还需  2
- 请求  2 ≤  2，系统可用资源  = 2 ≥ 2 →  分配成功
- 占有资源：P0=5,  P1=3, P2=4, P3=0*
- 系统可用资源  = 2 - 2 = 0

3.2  处理  P2 -> 2
- P2  当前占有  =  4，最大需求  = 7 →  还需  3
- 请求  2 ≤  3，但系统可用资源  = 0 < 2 →  阻塞
- 占有资源不变：P2=4*（被阻塞）
- 系统可用资源  = 0
