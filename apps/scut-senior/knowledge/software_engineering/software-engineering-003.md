软件工程与开发流程复习手册

一、软件工程与开发流程

1. 软件工程的核心目标

主要目标：降低软件复杂性、提高软件质量、保证可维护性，而不是简单地“编写更多代

码”。

可维护性：确保软件系统能够支持长期的修改、优化和升级，减少维护成本。

质量保证：通过系统化的方法、标准和流程提高软件可靠性和稳定性。

举例：

高内聚低耦合设计的模块比散乱代码更易维护。

自动化测试和持续集成可减少发布时的错误。

2. 软件生命周期

软件开发是一个持续演进的过程，通常分为以下阶段：

1. 需求分析

目标：准确理解和记录用户需求

方法：

访谈：与用户面对面沟通

问卷调查：收集大范围用户需求

原型法：快速制作系统原型，帮助用户明确需求

输出文档：需求规格说明书（SRS）

2. 系统设计

目标：根据需求设计系统架构和模块

包括：

系统架构设计

类设计（面向对象类图）

数据库设计（ER图、表结构设计）

3. 实现（编码）

<!-- page: 2 -->

将设计转化为可执行程序

强调编码规范、模块化和文档化

4. 测试

验证软件功能是否满足需求

发现并修复缺陷

测试类型：

单元测试

集成测试

系统测试

验收测试

5. 部署

将软件投入实际环境

安装、配置和上线

6. 维护

修复缺陷

系统升级和功能增强

性能优化

4. 面向对象设计三大特性

1. 封装（Encapsulation）

将数据和操作封装在类中

控制访问权限（public/private/protected）

优点：隐藏实现细节，降低模块间依赖

2. 继承（Inheritance）

子类继承父类属性和方法

支持代码复用

示例：

父类：动物
子类：狗、猫

3. 多态（Polymorphism）

同一操作作用于不同对象产生不同结果

支持接口统一调用不同实现

示例：

方法：makeSound()
对象：狗 → bark(), 猫 → meow()

5. 类间关系

泛化（继承）：父类和子类关系

关联：对象之间有联系，但不表示生命周期依赖

聚合：整体和部分的弱关系，部分可以独立存在

组合：整体和部分的强关系，部分依赖整体生命周期

三、简单回答的问题

## (1) 模块化的基本概念及在面向对象设计中的要点

模块化是将系统分解为若干独立的模块，每个模块独立承担一定的功能，减少模块间的依赖关
系。每个模块的设计应具有高内聚性（模块内功能紧密相关）和低耦合性（模块间依赖性小）。

面向对象设计中的要点：

封装：每个模块（或类）应该对外隐藏其内部实现，只暴露必要的接口。

继承：通过继承复用已有代码，避免重复开发。

多态：不同的模块可以通过相同接口调用不同实现，增强扩展性和灵活性。

(2) UML中的4+1视图及其作用

<!-- page: 9 -->

4+1视图模型是由Philippe Kruchten提出的，用于描述软件架构。包含以下5个视图：

1. 逻辑视图（Class Diagram / 类图）：描述系统的主要功能和类的关系。

主要作用：展示系统的静态结构，帮助理解系统如何运作。

2. 开发视图（Component Diagram / 组件图）：描述系统组件的组织和组件间的依赖关系。

主要作用：帮助开发团队理解各组件如何协同工作。

3. 过程视图（Sequence Diagram / 时序图）：描述系统的并发处理和执行流程。

主要作用：展示系统如何在时间序列上进行交互和处理。

4. 物理视图（Deployment Diagram / 部署图）：描述系统的硬件架构和部署情况。

主要作用：展示系统的运行环境和硬件资源如何配置。

5. 场景视图（Use Case Diagram / 用例图）：描述系统与外部参与者之间的交互。

主要作用：帮助捕捉用户需求和系统行为，确保系统满足用户需求。

(3) 白盒测试与黑盒测试的概念及测试方法

白盒测试：关注软件内部的逻辑结构和实现。测试人员需要了解程序的源代码。

测试方法：路径测试，测试程序中所有可能的执行路径，以确保所有路径都能正常执
行。

黑盒测试：关注软件的功能需求和输出，而不关心其内部实现。

测试方法：等价类划分，将输入分成有效类和无效类，从每个类中选择代表性数据进行
测试。

(4) 软件生命周期的主要阶段及重点工作

软件生命周期通常分为以下阶段：

1. 需求分析：确定用户需求和软件功能。

输出：需求文档。

2. 系统设计：制定系统的整体架构和各模块设计。

输出：设计文档、UML图。

3. 编码实现：将设计转化为代码，完成功能实现。

<!-- page: 10 -->

输出：源代码。

4. 测试：验证系统是否满足需求，检查系统的功能和性能。

输出：测试报告、缺陷报告。

5. 部署与维护：软件上线并进入维护阶段。

输出：部署文档、用户手册。

(5) 敏捷开发与瀑布模型的对比分析

敏捷开发：强调快速迭代、客户反馈和灵活应对需求变化。通过短周期的开发和频繁的交
付，确保软件能快速响应变化。

特点：灵活、迭代式、强调团队协作。

优点：适应性强，客户满意度高，快速交付。

瀑布模型：按照固定的顺序进行开发，每个阶段完成后才进入下一个阶段。比较适用于需求
明确、变化少的项目。

特点：顺序性、严格。

优点：管理明确，文档齐全。

(6) 评价软件产品质量的指标

1. 可靠性：系统在规定条件下完成任务的能力。

例如，系统无故障运行的时间。

2. 性能：系统的响应速度、处理能力。

例如，用户请求响应时间、系统并发处理能力。

3. 可维护性：系统易于修改和维护的能力。

例如，修改代码时不影响系统其他部分。

4. 可用性：系统的易用性和对用户的友好程度。

例如，系统界面设计的直观程度、操作流程的简洁性。

(7) 软件维护的类型及主要任务

1. 纠正性维护：修复系统中的缺陷。

<!-- page: 11 -->

2. 适应性维护：对系统进行修改，以适应环境的变化。

3. 完美维护：对系统进行优化，提高系统的性能。

4. 预防性维护：修改系统设计，预防潜在的缺陷和问题。

完美维护和纠正性维护是维护的主要任务，其中 纠正性维护 占比最大。

(8) 软件需求的主要类型及举例

1. 功能需求：描述系统需要执行的功能。

例如，“系统应能支持用户注册、登录功能。”

2. 非功能需求：描述系统性能、安全性等非功能性的要求。

例如，“系统应在高负载下响应时间不超过3秒。”

3. 业务需求：系统需要解决的业务问题。

例如，“系统需要支持在线支付功能。”

4. 技术需求：与开发技术和工具相关的要求。

例如，“系统使用Java开发。”

(10) 软件测试阶段的类型及目标

1. 单元测试：验证最小单元（函数、方法等）是否按预期工作。

对应文档：单元测试计划。

2. 集成测试：验证不同模块间的接口和交互是否正常。

对应文档：集成测试计划。

3. 系统测试：验证整个系统的功能和性能是否符合需求。

对应文档：系统测试计划。

4. 验收测试：由用户进行测试，确认系统是否满足需求。

对应文档：验收测试计划。

(11) 软件危机的典型表现及软件工程的目的

软件危机的表现：项目延期、成本超支、质量差、需求不明确、维护困难等。

软件工程的目的：提高软件开发的效率和质量，保证软件满足需求，降低开发成本。

主要研究内容：需求分析、设计方法、测试方法、项目管理等。

(12) 面向对象设计原则

1. 单一职责原则（SRP）：一个类只应有一个职责。

2. 开放封闭原则（OCP）：软件应对扩展开放，对修改封闭。

3. 里氏替换原则（LSP）：子类应能够替代父类出现在程序中。

4. 依赖倒置原则（DIP）：高层模块不应依赖低层模块，两者应依赖于抽象。

通过遵循这些原则，可以提高设计的灵活性和扩展性，减少系统变更时的影响。

(13) 常见的软件过程模型

1. 瀑布模型：严格的阶段性开发，每个阶段完成后才能进入下一个阶段，适合需求明确的项
目。

优点：管理简单，文档齐全。

缺点：不适应需求变化。

2. 敏捷开发模型：迭代式开发，快速交付，适应需求变化。

优点：灵活、快速响应变化。

缺点：文档不完善，管理复杂。

3. 螺旋模型：结合瀑布模型和迭代开发的优点，通过风险管理推进开发。

优点：可控风险，适应变化。

缺点：开发周期较长，适用大型项目。

4. V模型：每个开发阶段与一个测试阶段相对应，适合严格的质量要求。

优点：保证测试覆盖，质量高。

缺点：对需求变化适应性差。

四、分析题（15分）

题目 1

<!-- page: 13 -->

某医院要开发一款 “智能挂号系统”，用于患者快速预约挂号、查看排队情况、支付挂号费等。产
品经理提出以下需求：

A. 患者可以通过系统查看各科室的医生排班情况。

B. 系统需要支持至少500个患者同时进行预约操作。

C. 系统必须确保在高峰时段（如早上8-9点）预约响应时间不超过3秒。

D. 患者可以查看历史预约记录和缴费记录。

E. 管理员可以通过后台管理患者预约情况，进行数据统计和分析。

问题：

1. 请将这些需求划分为 功能需求、性能需求、和/或其他 非功能需求，并说明理由。

2. 画出该系统的 DFD（数据流图）。

3. 画出该系统的 核心功能的ER图。

解释：

这道题目和原题目类似，都是通过对一个实际系统的需求进行分析，将需求合理划分为不同类型
（功能性需求、性能性需求、非功能需求），然后通过数据流图（DFD）和实体关系图（ER图）
来帮助分析系统的结构和数据处理。DFD图帮助理解系统内部数据流动，而ER图则帮助理解系统
实体之间的关系。

五、UML 综合分析与设计题（15分）

题目 2

设计一个 “在线学习平台”，该平台允许学生观看课程视频、提交作业、与老师进行互动。教师可
以管理课程内容和评定学生作业。该平台还支持学生查看成绩和课程进度。

的交互顺序。通过这些 UML 图，帮助理解系统的设计和工作流程。
